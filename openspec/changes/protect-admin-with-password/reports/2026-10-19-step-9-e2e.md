# Step 9: E2E testing (JOS-173, protect-admin-with-password)

Date: 2026-10-19. Tool: `playwright-cli` (Chromium). Targets were found by role and accessible name.

## Setup

The real backend of this branch on port 3173 (scratch store and project folders, environment cleared, no credential, voice stub, and the same scratch-only content-check preload as step 8), and the Vite dev server on 5173 with `VITE_API_BASE=http://127.0.0.1:3173`. The page and the API are on different origins, so every Administrator call is a real cross-origin request with a preflight.

## Scenarios

1. **No password configured (9.1).** `/admin` showed the heading "Administrator" and a message: "No Administrator password is configured. Set `ADMIN_PASSWORD` in the environment or in the local secrets file, then restart the app. The regular pages do not need it." There was no password field and no button. (`screenshots/01-not-configured.png`)
2. **Restart with a password, reload (9.2).** The page showed the "Password" field and a disabled `Unlock` button (disabled until something is typed). (`02-locked.png`)
3. **A wrong password (AC2).** `Unlock` showed the alert "Wrong password"; the form stayed and no Administrator area appeared. (`03-wrong-password.png`, the password is masked)
4. **The right password (AC1).** The form was replaced by the region "Administrator tools" with "No Administrator tools yet". `localStorage` and `sessionStorage` were empty, `document.cookie` was empty, and the address was `/admin` with nothing added. (`04-unlocked.png`)
5. **Reload.** The form was back, `Unlock` disabled again, and storage still empty.
6. **Regular pages (AC3, 9.3).** `/` showed the start form with no password field and no `/admin` link. Filling it in and pressing `Start project` opened `/?sessionId=<id>` with the session page (heading, `Pause session`, the four phases), with no password asked. (`06-session-page-no-password.png`)
7. **Phone width.** At 375 px `scrollWidth` equalled `innerWidth`, locked and unlocked. (`05-locked-375px.png`)

The server log confirms the split: every `GET /admin/access` and both `OPTIONS /admin/access` preflights come from the visits to `/admin`; after the first request the start page and the session page made (`/app/update`, `/telemetry/consent`, `/languages`, `POST /sessions`, `GET /events`, `GET /sessions/<id>`), none touched `/admin/`.

## Defect found and fixed during this step

The first screenshot of the unlocked state (`04-unlocked.png`) showed "No Administrator tools yet" in a thin white pill with the text touching its left edge: the area used `card pop` but not the padding the form card gets from `start-form`. It is now `start-form card pop`, and the screenshot in this folder is the corrected one. The page tests (13) and the whole frontend suite (261) pass.

## Console

The favicon is not requested here. Chromium prints its own "Failed to load resource ... 401" line for each refused `GET /admin/access` (the first check on load, which carries no password, and the wrong-password attempt). Those are the expected refusals the page reads its state from; there are no React errors and no unexpected failed request.

## Restore

The browser was closed, the backend and the dev server stopped (ports 3173 and 5173 are free), and the scratch store, home folder and Playwright working files were deleted. `backend/data/` does not exist in this worktree.
