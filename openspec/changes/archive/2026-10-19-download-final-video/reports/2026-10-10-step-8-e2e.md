# Step 8 — E2E testing with the browser (JOS-164, download-final-video)

Real backend (`node src/server.ts`, scratch store/projects, `ALLOW_TEST_ENDPOINTS=1`) and real frontend (`vite --port 5184`), driven in an actual Chrome tab (Claude in Chrome).

## 8.1 — No final-video link while scenes are still processing

Session created via `quick-voice-over` + one `quick-scene` call (`USE_STUB_VIDEO_PROVIDER=pending`). Opened `http://localhost:5184/?sessionId=<id>`: session state `chunks-processing`, scene 1 `video-generating`, "Final video: Not started" — no download link anywhere on the page.

## 8.2 — The link appears live, without a reload

Restarted the backend in place (`USE_STUB_VIDEO_PROVIDER=success-bytes`, `USE_STUB_ASSEMBLY_TOOL=slow-success`, `ASSEMBLY_STUB_DELAY_MS=5000`, same `DB_PATH`/`PROJECTS_ROOT`), **without touching the open browser tab**. After ~4s (the SSE connection reconnecting and the delayed assembly finishing), the same tab — still "connected" — updated on its own: session state became `final-video`, "Final video: Complete", and **"Download final video"** appeared. No page reload at any point.

## Note: the bare stub assembly tool never writes real bytes

Same pre-existing limitation JOS-163's manual pass and this change's own step 7 report found: `USE_STUB_ASSEMBLY_TOOL` reports success without writing to `outputPath`. To actually exercise the download link (task 8.3) a file was placed directly at the recorded path (`final-video.mp4`, 38 bytes) — exactly what a real `ffmpeg` run would have left there — without touching any code.

## 8.3 — Following the link downloads the real file, no prompt

Clicked "Download final video". No navigation, no dialog. The browser saved `~/Downloads/final-video.mp4` (38 bytes — no prior file of that name existed). `cmp` against the project folder's own `final-video.mp4`: byte-identical. File removed after verification.

## 8.4 — Restore and cleanup

Tab closed, both scratch processes killed, scratch store/folder removed. Confirmed `backend/data/` (the default store) does not exist in this worktree — untouched throughout.
