## Findings

- ⚠️ **A completed session still offers Pause.** The first attempt paused a session at `final-video` (its assembly had already finished, because the stub delay was short). The store recorded `paused = true` and the page showed the button. Nothing is held and no request is sent, so it is harmless, but a finished session offering Pause is odd. It predates this change (the pause route does not check the state) and is not fixed here.
- 🔍 Pause and continue during an assembly do not interrupt it, and continue starts no second attempt. This is the behaviour the change is for.
- 🔍 The stub assembly does not write `final-video.mp4`, so the download link is shown but its file is absent. The browser check verified the link is offered, not that it downloads (the curl step recorded the same limitation).
