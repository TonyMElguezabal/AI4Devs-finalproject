# Step 9 — Browser E2E (JOS-151)

Date: 2026-10-02. Chrome via the browser automation tools; backend on a scratch store (`DB_PATH` and `PROJECTS_ROOT` in the scratchpad), frontend on the Vite dev server.

## Setup (9.2)

- Backend on port 3151 with the scratch store; session created and paused; three scenes seeded directly:
  - scene 1: `image-complete`, a real 8x8 PNG stored.
  - scene 2: `failed` (affected stage `image`), no stored image.
  - scene 3: image stored, then `failed`.
- The backend hard-codes `affectedStage` to `image` for failed scenes (no column), so it cannot produce a `video` failure. A throwaway proxy on port 3100 (the frontend's default API base) forwarded to the backend and rewrote `affectedStage` to `video` for scene 3 in the JSON read and SSE payloads. Everything else, including image bytes, passed through unchanged (verified with `cmp`).
- Note: Vite listens on IPv6 only here, so the app was opened at `http://localhost:5173/`, not `127.0.0.1`.

## Findings (9.3)

| Scene | Observed after expanding |
|---|---|
| 1, image-complete | image "Scene 1 image" loaded from `<API>/sessions/<id>/scenes/<id>/image`, natural width 8; no error, no stage row, no retry/correction |
| 2, failed (image) | error text, "Affected stage: image", "Retry scene 2" button and the correction form |
| 3, failed (video) | error text, "Affected stage: video", the stored image, and no retry button and no correction form |

Defect found: the image stretched to the full panel width (the details panel is a flex column and had no sizing rule). Fixed by adding task 4.6 and a `.scene-image, .scene-clip` rule (`align-self: flex-start`, `max-width: 100%`, `max-height: 240px`, `object-fit: contain`). After reload the images render at their natural 8x8 size.

## Live update (9.4)

With the page open (a `window` marker proved no reload happened), "Continue session" was clicked. Scene 2 went from `failed` to `image-complete` in the row: the error, "Affected stage" row, retry button and correction form disappeared and an image element appeared. Scenes 1 and 3 were untouched.

The new image has width 0 in the browser because the stub provider writes placeholder text into a `.png`. The route served it correctly (200, `image/png`, the file's bytes); the real provider writes real image bytes.

An earlier click on "Retry scene 2" while the session was paused changed nothing (the endpoint answers 200 without acting on a paused session); this is existing behaviour outside this change.

## Restore (9.5)

Servers stopped (ports 3100, 3151, 5173 free), browser tab closed, default store `backend/data/skeleton.sqlite` empty, scratch files stay in the scratchpad. Frontend suite: 58 passed; `tsc --noEmit` clean.
