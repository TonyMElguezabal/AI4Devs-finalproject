# Step 9 Report — E2E Applicability (task 9.1)

- Date: 2026-10-02
- Change: request-admitted-clip-duration (JOS-147)

## Decision: not applicable

This change adds two optional, read-only fields (`requestedDurationSeconds`, `durationWarning`) to the scene response and scene events. No frontend file is touched, and the frontend does not read either field:

- `frontend/src/components/SceneRow.tsx`'s own existing comment (predating this change): *"PRD §3/§7.2/AC23 also calls for narration interval, requested duration and speed factor in scene details; those come from stories this skeleton does not model (US-15, the media pipeline) and are left out here rather than faked."* — the frontend already, explicitly, defers rendering the requested duration to JOS-148 (US-15).
- `frontend/src/types.ts`'s `SceneEventPayload` does not declare `narrationInterval` either (JOS-143's own equivalent field), confirming the frontend's scene type has not been extended for any of this backend-side work yet, by design.
- A `grep` across `frontend/src` for `requestedDurationSeconds` and `narrationInterval` finds zero occurrences.

Two additional, backend-only, optional response fields that nothing in the frontend parses or renders change no observable behaviour on the session page. There is nothing for a Playwright check to exercise that groups 2-8's curl-based verification (task 8.2-8.5) did not already cover more directly, against the real HTTP contract.
