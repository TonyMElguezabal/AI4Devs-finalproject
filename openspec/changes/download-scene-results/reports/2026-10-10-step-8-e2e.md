# Step 8 — E2E testing with the browser (JOS-163, download-scene-results)

Real backend (`node src/server.ts`, scratch store/projects, `ALLOW_TEST_ENDPOINTS=1`) and real frontend (`vite --port 5183`), driven in an actual Chrome tab (Claude in Chrome).

## 8.1 — A video-generating scene offers only its image download

Session created via `quick-voice-over` + one `quick-scene` call (`USE_STUB_VIDEO_PROVIDER=pending`). Opened `http://localhost:5183/?sessionId=<id>`, expanded scene 1's details while it was `video-generating`: the page showed exactly one download link, **"Download scene 1 image"** — no clip link, and no MP3, timestamps or generated-texts download appears anywhere on the page (confirmed in `frontend/test/components.test.tsx` too; nothing in the markup even has that affordance).

## 8.2 — Following the image link downloads the real file

Clicked "Download scene 1 image". No navigation, no prompt. The browser saved `~/Downloads/scene-1-image.png` (no prior file of that name existed). `cmp` against the project folder's `scene-1.png`: byte-identical. File removed after verification.

## 8.3 — Clip links appear live, without a reload

Restarted the backend in place (`USE_STUB_VIDEO_PROVIDER=success-bytes`, `USE_STUB_ASSEMBLY_TOOL=success`, same `DB_PATH`/`PROJECTS_ROOT`), **without touching the open browser tab**. After ~5s (the SSE connection reconnecting), the same tab — still showing "connected" — updated on its own: scene 1 went to `chunk-complete` and **"Download scene 1 video"** appeared next to the image link, with session state reaching `final-video`. No page reload at any point.

## 8.4 — Restore and cleanup

Tab closed, both scratch processes killed, scratch store/folder removed. Confirmed `backend/data/` (the default store) does not exist in this worktree — untouched throughout.
