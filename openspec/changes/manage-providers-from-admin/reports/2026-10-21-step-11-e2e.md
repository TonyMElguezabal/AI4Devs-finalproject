# Step 11: end-to-end test in the browser (JOS-218, manage-providers-from-admin)

Date: 2026-10-21. Branch `feature/jos-218-manage-providers-from-admin`. Driven with Chrome (the Claude in Chrome tools, not Playwright MCP). The backend ran on port 3190 with the launcher of step 10 (the real image adapter and provider profiles with the network intercepted, stubs for the other stages, a scratch store and key file, `ADMIN_PASSWORD` and `FAL_API_KEY` set) and the real frontend ran on Vite at port 5173 with `VITE_API_BASE=http://127.0.0.1:3190`. Port 3100 was in use by another process and was left alone.

## 11.1 Applicability

A new `/admin` section: the step applies.

## 11.2 Without and with the password

Without it, `/admin` shows only "Administrator", the password field and Unlock: no provider is listed or changeable. After unlocking, "Active providers" (the five selectors of JOS-171) is followed by "Providers": per stage the profiles with their adapter type, key status and hint, and the reasons a profile is not usable. The five profiles created from the settings showed `Key missing` (reasoning, voice, alignment, video, with the reason "no API key is stored or found for this provider") or `Key from the environment` (image), each marked Active.

## 11.3 Add, edit, choose, reload

- **Add:** "Add image provider" opened a form with Name, Model and API key; the key field is a password input. Name "Flux schnell", model `fal-ai/flux/schnell` and a scratch API key were saved: the form closed, the list showed "Flux schnell, Fal.ai, Key stored (…abcd)", and the image selector under "Active providers" now offered "Flux schnell" without a reload.
- **Edit:** "Edit Flux schnell" showed the name and the model, an **empty** password-type key field and "Leave empty to keep the current key". The model was changed to `fal-ai/flux/schnell-v2` and saved with the key field left empty: the key stayed (`…abcd`).
- **Choose:** the image selector was set to "Flux schnell": it showed "set on /admin".
- **Reload:** after reloading `/admin` and unlocking again, the selector still showed Flux schnell and the list marked it Active.

Finding fixed during the run: the "Active" badge in the list did not move when the selector changed. `ActiveProvidersSection` now tells `AdminTools` (`onChanged`), which reloads the list through a new `refreshKey`; both directions are covered by new component tests and the badge then moved to the chosen provider at once.

## 11.4 Delete

| Action | Result |
| --- | --- |
| delete "Flux schnell" while it is the active image provider | the page said "Flux schnell is the active image provider; choose another provider first." and kept it listed |
| a session ("E2E B") was started while it was active; its scenes bound to it and the intercepted requests went to `https://fal.run/fal-ai/flux/schnell-v2` with the key entered above | both scenes `chunk-complete` |
| choose Fal.ai as active, then delete "Flux schnell" | "Flux schnell was retired: sessions are still bound to it, so it is no longer offered but keeps serving them."; the list and the selector then showed only Fal.ai |
| add "Temp", then delete it | "Temp was removed." |

## 11.5 Diagnostics

Session E2E B's scene details showed `Image: Flux schnell (fal-ai/flux/schnell-v2), 1 attempt` (the name and model of the retired profile its scene is bound to), `Voice-over: ElevenLabs (eleven_multilingual_v2)`, `Timestamps: ElevenLabs (forced alignment)`, `Scene instructions: OpenAI (gpt-6-astra)` and `Clip: RunningHub (minimax/hailuo-h3)`; no "Unknown provider".

## 11.6 Restore

Both servers were stopped, the scratch folder (store, projects, key file, logs) was deleted and ports 3190 and 5173 are free. `backend/data/` does not exist, so the default store was untouched, and no `.secrets.json` was created.
