No UI change, but AC4 ("waiting is not shown as failed") is visible on the session page, so it applies.

Backend on port 3100 with a scratch store and projects folder, `USE_STUB_VOICE_PROVIDER=success-after-limit`, `VOICE_STUB_DELAY_MS=8000`. Frontend on the Vite dev server (5173). The voice cap is the real value, 3, so four sessions were started within a second (the plan's "voice limit 1" has no environment override; one more session gives the same queueing). Read from the store: sessions e1 to e3 `in-flight`, e4 `scheduled`.

## Result

The session then showed "Decomposition Failed: missing credential 'ELEVENLABS_KEY'". That is the environment (no provider credentials in the scratch run), not the cap, and happened after the voice-over completed.
