# Step 10: E2E testing (JOS-168, view-progress-by-phase)

Date: 2026-10-04. Tool: `playwright-cli` (the Playwright command line from the project's `playwright-cli` skill; no Playwright MCP was available). Elements were located from the accessibility snapshot by role and accessible name.

## Environment

- Backend: `node src/server.ts` on port 3199, scratch `DB_PATH` and `PROJECTS_ROOT` in the session scratchpad.
- Frontend: Vite on port 5199 with `VITE_API_BASE=http://127.0.0.1:3199`. Port 5173 was already held by a Vite process that this session did not start, so it was left alone.
- Sessions were created with `POST /sessions`. State the product cannot yet produce without a provider (a stored narration, a recorded failure, an in-flight attempt, a submitted scene) was written to the scratch store by a small seed script. Those writes bypass the server, so a `POST /pause` was used to make the server broadcast the new snapshot to the open page. `/continue` was never called, so no provider was reached.

## Scenarios

1. **Four sections in order (10.2).** Opening a new session showed the regions `Voice-over phase`, `Decomposition phase`, `Scenes phase` and `Final video phase`, in that order, each headed with `Not started`. The scenes section held `Scenes are not yet available.`.
2. **Live update without reload (10.3).** With the page open on that session, a narration and a scene were seeded and the session paused. The page, with no reload, changed to `Voice-over Complete`, `Decomposition Complete`, `Scenes In progress`, with the scene row `Scene 1` inside the Scenes section and the header reading `chunks-processing — paused (1 image held)`.
3. **Decomposition failure (10.4).** A second session with a recorded decomposition failure showed `Decomposition Failed` with an alert carrying the cause (`The narration's timestamps could not be obtained: alignment timed out.`) and no button inside the section. The header kept `failed` and `Failed phase: decomposition`.
4. **Retry in flight (10.4).** After an in-flight `timestamps` attempt was recorded and the snapshot broadcast, the same open page showed `Decomposition In progress`, the alert gone, and the header state `chunk-decomposing`, with no reload.
5. **Held work (10.5).** On the first session, the Scenes section showed `Waiting for you to continue (1 held)` and the scene row `waiting for continue`, alongside the header's paused marker `— paused (1 image held)` and the `Continue session` button. The Voice-over and Decomposition sections showed no held text.

A screenshot of scenario 5 was reviewed: the sections use the status colour of their state (complete green, in progress amber, not started grey) with the label text beside the colour.
